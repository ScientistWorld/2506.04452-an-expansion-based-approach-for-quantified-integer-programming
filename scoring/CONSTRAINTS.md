# Scientist Constraints

These are the things a future scientist must keep fixed when claiming an
improvement over this workspace.

## Benchmark Family

- Task: satisfiability solving for quantified integer programs.
- Benchmark family: QRandomParity instances generated by `data/qrandomparity.py`.
- Active scored setting: `qrandomparity_n10`.

## Data and Generation

- Keep the QRandomParity semantics unchanged.
- Keep the active scored batch fixed at 100 generated instances for `n=10`.
- Reuse the same seed schedule implemented by the runner scripts unless you are
  adding a new experiment under a new name.

## Evaluation Contract

- Keep the path `scripts/evaluate.sh -> eval/evaluate.py` usable for both the
  proposed solver and the baseline.
- Continue to report both `median_runtime_s` and `instances_solved`.
- Do not count a runtime win if it comes from solving fewer instances.

## Comparison Discipline

- Compare the candidate solver and the search baseline on the same generated batch.
- Do not simplify the parity encoding, shorten the quantifier prefix, or reduce
  the universal interaction while keeping the same experiment name.
- If you add a larger or smaller benchmark, record it under a new experiment
  name instead of mutating `qrandomparity_n10`.
