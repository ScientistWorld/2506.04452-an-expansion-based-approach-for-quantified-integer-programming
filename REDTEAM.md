Genuine improvement scores higher in the controlled comparison, and a clearly weaker solver scores lower, both beyond the measured seed spread. **The gym still does not reliably reward scientific contribution:** a constant, entirely wrong answer beats the reference, reported runtimes are trusted, and missing candidate results can tie the reference. **The test is too small:** exact enumeration solves every test instance within the five-second limit. The scaled task retains the paper's parity construction and a runtime gap, but does not establish its scalability advantage over search.

These comparisons use the locally supplied [paper](paper/2506.04452.md), especially Sections 3, 5.1 and Appendix A.1. The shortcut implementations do not read the paper or hidden IDs. The generator matches the QIP parity construction, but every generated instance has the same answer: the two chains compute the same parity of the outer variables; u=0 forces that parity to 1 and u=1 forces it to 0. Because the outer assignment precedes u, every instance is UNSAT. This follows from visible [data/qrandomparity.py](data/qrandomparity.py), and the exact baseline independently confirmed the batch. Random permutation changes representation without hiding the answer. Consequently, this task can measure backend speed on parity contradictions but cannot distinguish a better general QIP method from a family-specific constant answer.

The reference can be beaten. None of its four active test metrics is at its mathematical bound: runtimes are positive and coverage is 49/50. The full-batch reference in `reference.json` similarly has positive runtimes and 99/100 coverage. The complete list of scored reference metrics already at a bound is `qrandomparity_n100.instances_unsolved = 0` and `qrandomparity_n200.instances_unsolved = 0`; both have the lower bound zero. The same is true for those paper-context comparator counts. The active enumeration baseline's 50/50 coverage is at its bound. Both n100 and n200 remain in the coefficient schema with weight 0.15 each, but the hidden evaluator writes neither experiment for any method. Their improvements are therefore skipped; 30% of declared experiment weight has no active measurement.

For the active experiment the rank is

`0.7 * (0.8*(ref_median-median)/sigma_median + 0.4*(solved-ref_solved)/sigma_solved + 0.3*(ref_mean-mean)/sigma_mean + 0.7*(ref_p90-p90)/sigma_p90)`.

The negative runtime coefficient signs do not reverse their directions; only their magnitudes count. All timing improvements are divided by timing variability, so changing units does not change their intended weight. The three timing metrics are additive against coverage, rather than a correctness/coverage gate. In particular, a method that fails the entire task can outrank the reference: the constant SAT shortcut has zero correct answers but strictly better values on every scored metric. No choice of positive metric scales can fix that ordering.

The report schema and seeds are visible to future agents through the train evaluator, runners, baseline and generator. Every shortcut emits all 100 public IDs; none depends on the hidden partition, frozen score values, or a hidden artifact. Constant answers and cache replay also work without the supplied method implementation. Saved reports are the artifact the evaluator trusts: it does not regenerate problems, compare SAT/UNSAT with ground truth, verify a witness/strategy, measure execution, or enforce the five-second metadata value. Writing status and timing fields is enough; writing top-level aggregate scores is not. There is no fixed trained model or detector to retrain in this gym. Baseline replacement tests the applicable comparison-artifact path; changing that report does not change candidate rank.

Failed runs do **not** always receive worst values for every metric and experiment. Explicit TIMEOUT records with honest five-second metadata do receive (5,0,5,5), as the weaker run demonstrates. In contrast, an empty candidate has no `available_n`, bypasses its slice validation, and disappears. Experiment completeness is checked across all solvers together, so the baseline satisfies it. The rank's missing-value rule then turns a total candidate failure into a neutral shortcut tie. Partial records and null timings instead abort evaluation, leaving stale output; this audit treats both as failed evaluations, never as wins. The discovery script searches only `tmp/results`, `checkpoints`, and `outputs`. It cannot write every method on disk into `results`, as the unscanned shortcut demonstrates.

All runs used the original hidden script and evaluator, with their hashes checked against [initial/hashes.json](redteam/initial/hashes.json). The method-only backend changes occurred in the producer process and ended before evaluation. There were no evaluator modifications or Python-environment alterations. The bundled job reused measured reference/baseline outputs for report-only shortcuts, with per-case evidence kept separately. [redteam/README.md](redteam/README.md) documents rerunning. Gym source files, scoring targets, original scores, and `scripts/run.sh` have been restored with git. Preexisting unrelated workspace changes recorded in [initial/git_status.txt](redteam/initial/git_status.txt) are preserved; required scheduler metadata is handled separately.

For the next iteration, the consequential fixes are to execute and time each candidate inside evaluation, check decisive answers, require complete per-method coverage with explicit worst values on failure, and move to hidden inputs and sizes where enumeration no longer solves everything. Scoring must either actively measure n100/n200 or remove their coefficients. Correctness and required coverage need to be enforced before runtime improvements are ranked. No gym fixes were applied as part of this audit.
